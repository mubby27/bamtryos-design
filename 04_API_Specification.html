01
API Overview
Global conventions, versioning, and format standards
Base URL
api.bamtryos.com/v1
All endpoints are prefixed with the base URL and API version.
Protocol
HTTPS + WSS
TLS 1.3 enforced. Plain HTTP redirected to HTTPS.
Auth Method
DID-JWT
Bearer token signed by the user's DID private key.
ℹ️
Response envelope: All API responses follow a consistent envelope: { "success": bool, "data": T, "error": ErrorObject | null }. Pagination uses { "items": T[], "cursor": string, "hasMore": bool }.

02
Authentication
DID-based challenge-response authentication flow
1
Request Challenge
Client sends its DID to the Auth Service and receives a one-time nonce challenge string valid for 5 minutes.
2
Sign Challenge
Client signs the challenge with its DID private key (inside the TEE). The signature proves key ownership without transmitting the key.
3
Exchange for JWT
Client sends DID + signature to the server. Server verifies via the DID Document public key and returns a signed JWT (1 hour TTL) + refresh token (30 days).
4
Use Bearer Token
All subsequent requests include the JWT as Authorization: Bearer {token}. Refresh using the /auth/refresh endpoint before expiry.

09
WebSocket Events
Real-time event stream — wss://api.bamtryos.com/v1/ws
ℹ️
Connection: Connect with Authorization: Bearer {token} and X-Bamtry-DID headers. All messages are JSON. Subscribe to event channels by sending a { "type": "subscribe", "channel": "..." } frame after connecting.
transaction:updateServer → Client
Emitted when a pending transaction's status changes (pending → confirmed / failed). Includes chain, txHash, confirmations, and final status.
balance:updateServer → Client
Emitted when on-chain balance changes are detected for any linked address. Includes chain, address, new balance, and USD value.
agent:streamServer → Client
Token-by-token streaming response from the AI agent when stream:true is set in /agent/chat. Each frame contains a delta string.
device:pair:completeServer → Client
Fired to the originating device when a new device successfully pairs using the QR token. Includes new device metadata.
notification:pushServer → Client
General-purpose push notification envelope for system alerts, dApp events, and credential offers.
pingClient → Server
Keepalive heartbeat. Server responds with pong. Send every 30 seconds to maintain connection.

INTERNAL_ERROR500Unexpected server error. Request ID is in X-Bamtry-Request-ID header for debugging.

Rate Limits
Per-DID throttling and burst allowances
Endpoint GroupRate LimitBurstNotes
/auth/* 10 req / min 20 Per IP address, not DID
/identity/* 60 req / min 120 Per DID
/wallet/transaction/* 30 req / min 50 Per DID — broadcast endpoints are stricter
/storage/upload 10 req / min 20 Additionally capped at 1GB / day per DID
/agent/chat 20 req / min 30 Token usage limits apply per tier
All other endpoints 120 req / min 200 Per DID
⚠️
Rate limit headers: All responses include X-RateLimit-Limit, X-RateLimit-Remaining, and X-RateLimit-Reset (Unix timestamp). When limited, the response is 429 with a Retry-After header.
