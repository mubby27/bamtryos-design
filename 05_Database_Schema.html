01
Overview & Entity Relationships
Storage layer architecture and entity relationship summary
PostgreSQL (Primary)
  • Relational data: users, wallets, transactions, apps
  • ACID compliance for financial records
  • UUID primary keys, row-level security
  • Encrypted PII columns via pgcrypto
Redis (Cache + Queue)
  • Auth challenge nonces (5min TTL)
  • Session tokens and rate limit counters
  • Real-time event queue (pub/sub)
  • Balance cache (30s TTL per chain)
ClickHouse (Analytics)
  • Append-only event and telemetry tables
  • No PII — DIDs are pseudonymous
  • Columnar storage for fast aggregations
  • Retention: 90 days raw, 2 years aggregated

ClickHouse Analytics Tables
Append-only columnar store for usage telemetry — no PII
⚠️
Privacy by design: ClickHouse tables store DIDs (pseudonymous) but never IP addresses, device fingerprints, or any data that could be personally linked outside BamtryOS. Raw events are purged after 90 days; aggregated summaries are retained for 2 years.
📊
events
All user-action events — screen views, feature usage, errors
ClickHouse
ColumnTypeDescription
event_dateDatePartition key — used for TTL and range queries
event_timeDateTime64(3,'UTC')Millisecond-precision event timestamp
did_hashFixedString(64)SHA-256 of DID string — pseudonymous user identifier
event_nameLowCardinality(String)e.g. wallet.send, dapp.install, agent.chat
platformLowCardinality(String)android | ios | windows | macos | linux | web
chainLowCardinality(String)Active chain context at time of event (nullable)
propertiesMap(String, String)Arbitrary key-value event properties (no PII)
session_idUUIDApp session ID for funnel analysis
ENGINE = MergeTree() PARTITION BY toYYYYMM(event_date) ORDER BY (event_name, did_hash, event_time) TTL event_date + INTERVAL 90 DAY

On-Chain Storage
Smart contract state — only anchoring hashes and DID registrations
ℹ️
Principle: We store the minimum possible data on-chain — only immutable anchors (DID CID hashes, file ACL hashes) and financial state (token balances, smart contract state). All mutable metadata lives off-chain in PostgreSQL and IPFS.
⛓️
DIDRegistry.sol (EVM)
Stores the mapping from Ethereum address → latest DID Document CID

Migration Strategy
Schema versioning, rollback policy, and tooling
Tooling
  • Flyway for PostgreSQL migrations — SQL-based, version-numbered
  • Migrations live in db/migrations/ as V{n}__{name}.sql
  • Applied automatically on service startup via CI/CD
  • ClickHouse DDL managed separately via Liquibase
Conventions
  • All migrations must be non-destructive (add-only in production)
  • Column drops in a separate cleanup migration, one release later
  • Every foreign key has an explicit index
  • All timestamps in UTC TIMESTAMPTZ — no bare TIMESTAMP
Rollback Policy
  • Each migration has a paired undo script in db/undo/
  • Feature flags gate new schema-dependent code paths
  • Blue-green deploys allow rollback at the service level
  • Critical migrations require DBA review sign-off before merge
